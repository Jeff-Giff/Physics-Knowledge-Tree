# 中文物理知识树 — 编辑指南

## 1. 项目结构速览

```
physics-knowledge-tree/
├── site/                 # 可视化网站（双击 index.html 即可离线打开，勿手动改 data/graph.js）
├── content/              # 知识树源文件（本 skill 主要操作此目录）
│   ├── _meta.yaml        # 领域/颜色/云图参数/可视化参数
│   └── <domain>/*.md     # 每个知识点一个 .md 节点文件
├── build.py              # 构建脚本：解析 content → site/data/graph.js + 校验
├── logs/YYYY-MM-DD.md    # 每次编辑的日志
└── skills/physics-knowledge-tree/SKILL.md  # 本文件
```

## 2. 标准工作流（每次编辑必须遵守）

1. **先搜索再新建**：检查 `content/` 中是否已存在同名或同义节点（用 `grep` 搜索中文名/别名），避免重复节点。
2. **编写/修改节点文件**（格式见下节）。
3. **运行校验**：`python build.py`，修复所有警告（warning）。要求 0 警告。
4. **写日志**：在 `logs/` 下追加（或新建）当天的 `YYYY-MM-DD.md`，记录新增/修改的内容（见第 7 节）。
5. 若需要，提示用户重新打开/刷新 `site/index.html` 查看效果。

## 3. 节点文件格式（核心）

节点分两类：**课程节点**（id 以 `c-` 开头，本科课程，参考北大/清华本科培养方案）与**研究方向节点**（id 以 `r-` 开头，物理按 arXiv Physics 顶层类别、数学按 arXiv math + 教育部 0701、生命科学按 arXiv q-bio、计算机按 arXiv cs、信息按 arXiv eess、化学按教育部 0703 + GB/T 13745、工程按教育部工学 08 大类二级学科归并）。每个节点 = YAML front-matter（元数据）+ Markdown 正文。

front-matter 模板：

```markdown
---
id: c-quantum-mechanics         # 必需。kebab-case，c- 课程 / r- 研究方向前缀，全树唯一
name: 量子力学                  # 必需。唯一，勿与其他节点重复
name_en: Quantum Mechanics      # 可选
domain: c-core                  # 必需。对应 _meta.yaml 中的领域 id（课程 5 类 c-*、研究 12 类 r-*）
aliases: [量子力学(I)]           # 可选。供搜索
tags: [标签]                    # 可选
keywords: [关键词]               # 可选。补充搜索
updated: 2026-08-13             # 与日志日期一致
size: 60                        # 可选。手动覆盖节点体积；缺省自动由连接数计算
links:
  - {id: c-atomic, type: prereq, note: 原子物理的实验事实与本课程衔接}
  - {id: c-group-theory, type: related, note: 对称性语言相互支撑}
---
```

正文模板（课程节点）：

```markdown
# 课程名

## 课程概述
课程定位、在培养方案/先修链中的位置。

## 主要内容
- 模块 A：……
- 模块 B：……

## 先修与后续
先修 [[c-xxx]]；后续 [[c-yyy]]，通向研究方向 [[r-zzz]]。
```

正文模板（研究方向节点）：

```markdown
# 方向名

## 方向概述
研究对象与对应的 arXiv 类别。

## 核心问题
- 问题 A：……

## 代表方法与设施
……

## 与其他方向的联系
- [[r-xxx]]：……
```

### `[[id]]` 与 `[[id|显示名]]`
正文中用双链引用其他节点，`build.py` 会校验目标是否存在（不存在的目标会报警告）。引用时显示节点名，如需不同文字用 `[[id|自定义文字]]`。

## 4. 字段语义

| 字段 | 说明 |
|---|---|
| `id` | 英文 slug，**一旦创建不要改名**（会被其他节点引用）。如确需改名，必须全局搜索替换所有引用。 |
| `name` | 中文名，唯一。避免同义词节点（如"量子力学"与"量子理论"只应有一个）。 |
| `domain` | 领域 id，须在 `content/_meta.yaml` 的 `domains:` 中定义。 |
| `links[].type` | 关系类型，**必填**，仅两种取值：`prereq`=先修（有方向：目标是学习本节点前应先掌握的内容，图上渲染为带箭头的连线，箭头按知识流向**由先修指向后继**）；`related`=相关（无方向，共享概念/方法、可相互参照）。先修边在图上距离更近、展示优先。 |
| `links[].note` | 关系说明，会展示在详情面板。 |

## 5. 连接管理规则

- 关系只有两种：**先修（prereq，有方向）**与**相关（related，无方向）**，不再有权重等级，也不再有上位替代。
- `prereq` 的方向约定：在节点 A 中写 `- {id: B, type: prereq}` 表示"**B 是 A 的先修**"（学 A 之前应先掌握 B）。先修关系**只由"后续方"声明一次**（课程由课程声明、研究方向由方向节点声明指向其入口课程），构建器会自动为双方生成连线与详情页分组；不要两边重复声明，更不要互相声明（循环先修会报警告）。
- `related` 是对称关系：只在一侧声明一次即可成边；同一对节点不要重复声明。
- 课程层典型先修链：数学基础 → 普通物理 → 四大力学 → 专业选修 → 研究方向；研究方向节点以 `prereq` 指向其入口课程（如 `r-superconduct` → `c-solid-state`）。
- 若同一对节点一边声明 `prereq`、另一边声明 `related`，按 `prereq` 处理并给出警告。
- 系统中每个节点最多展示 `max_visual_degree`（默认 8）条直接连线，**先修边优先保留**；超出部分自动降级为"软连接"（详情面板 + 2D 视图外圈显示）。**你仍然可以自由写更多 links**——系统自动处理展示剪枝。

## 6. 内容写作规范

**定位**：节点是"课程"与"研究方向"的导航条目，面向物理专业本科生与准研究生——讲清"这门课/这个方向是什么、学什么/研究什么、与上下游的关系"，而不是教材式展开。

**篇幅**：每个节点正文 200~600 字，概述式；确有必要可少量使用 KaTeX 公式。

**章节要求**：
- 课程节点：`## 课程概述`、`## 主要内容`、`## 先修与后续`（用 [[id]] 引用先修/后续节点）。
- 研究方向节点：`## 方向概述`（注明对应 arXiv 类别）、`## 核心问题`、`## 代表方法与设施`、`## 与其他方向的联系`。

**专业严谨性**：
- 课程设置以清北等校物理系培养方案为准；研究方向划分以 arXiv 分类为准，不写无来源断言。
- `[[id]]` 只指向已存在的节点（`build.py` 校验，保持 0 警告）。

## 6.1 分批扩充流程

- 按层分批推进（优先级：数学基础 → 普通物理 → 四大力学 → 实验与计算/专业选修 → 各研究类别）。
- 每批完成若干节点后：`python build.py` 要求 0 警告，并在 `logs/` 追加日志（新增/修改节点、批次范围）。
- 扩充既有节点时：保留 front-matter 的 `id/name/domain`，可补 `aliases/keywords`；仅改写正文；`updated` 更新为当天日期。

## 7. 日志规范

每次编辑会话**必须**在 `logs/` 写入（或追加）当天文件。格式：

```markdown
# 2026-08-12 编辑日志

## 新增节点
- 电动力学/麦克斯韦方程组.md —— 统一电磁学，预言电磁波
- 量子力学/薛定谔方程.md —— 量子力学基本方程

## 修改节点
- 经典力学/牛顿力学.md —— 补充先修：微积分、矢量微积分

## 新增/修改连接
- 电动力学 → 麦克斯韦方程组（prereq）
- 牛顿力学 → 狭义相对论（related）

## 说明
（补充任何决策或待办事项）
```

日志中的日期应与相关节点的 `updated` 字段一致。

## 8. 新增领域（domain）

如需添加领域（如"核物理"、"等离子体"）：

1. 在 `content/_meta.yaml` 的 `domains:` 下添加条目，格式：
   ```yaml
   nuclear-physics:
     name: 核物理
     color: "#fdcb6e"
     cloud_alpha: 0.09
     cloud_r: 1.0
   ```
2. `color` 用十六进制，遵循学科色相约定：**课程层低饱和度偏灰、研究层高饱和**；色相区间：数学=紫色（约 266°~280°）、物理=蓝紫至蓝绿（约 250°→170°）、化学=绿至黄绿（约 122°→95°）、生命科学=黄绿至黄（约 78°→56°）、信息/计算机/工程=紫红至粉红（约 306°→350°）。新领域在所属学科区间内选色，与相邻领域错开明度以便区分。
3. 在 `content/nuclear-physics/` 下建目录并写节点。
4. 运行 `build.py` 确认领域出现在图例与统计中。

## 9. 校验与构建

```bash
cd physics-knowledge-tree
python build.py            # 构建 + 校验，输出统计与警告
```

预期结果：
- `0 警告`；若有警告必须逐个修复（多为：引用不存在的节点 id、重复 id、领域未定义、links 缺少合法 type、循环先修、`[[id]]` 指向不存在节点）。
- 构建会输出节点数、连接数（先修/相关）、领域分布。
- `site/data/graph.js` 由脚本生成，**禁止手改**。

## 10. 常见错误与排查

| 症状 | 原因与处理 |
|---|---|
| `[文件] 重复 id` | 该 id 已被其他文件使用，换个唯一 id。 |
| `link 指向不存在的节点` | 先创建目标节点，或删掉该链接。 |
| `[[xxx]] 引用了不存在的节点` | 正文双链指向了未创建的 id，修正为已存在的 id。 |
| `领域 'x' 未定义` | 在 `_meta.yaml` 中补领域。 |
| 图里看不到新节点 | 先跑 `python build.py`，再刷新 `site/index.html`。 |
| 图例不显示新领域 | `_meta.yaml` 领域 id 与节点 `domain` 不一致。 |

## 11. 网站使用提示（供参考，无需修改）

- 打开 `site/index.html` 即 3D 全局视图：滚轮缩放、拖拽旋转。
- **单击节点**：高亮该节点、与之相连的所有节点与路径（其余节点/连线弱化）。
- **双击节点**：进入该节点——切换为 2D 平面视图（该节点居中 + 全部相连节点），右侧详情抽屉显示内容与公式。
- 2D 视图中：单击高亮、双击切换中心；点击空白或"← 返回 3D 全局"返回。
- 顶栏"字号"滑杆调节 3D 节点标签字体（刷新后保留）；"间距"滑杆（2D 模式显示）调节节点间距，节点可自由拖动（释放后固定），"重置布局"复位。
- 顶部搜索框按名称/别名/标签/关键词检索，回车/点击直接跳转进入节点。
- "领域图例"可逐域隐藏；"标签"开关节点文字。
- "分类高亮"（仅 3D）打开右侧多选侧边栏：勾选领域后仅亮起这些领域的节点与内部连线，"全选 / 清空"一键操作；与单击高亮叠加时单击优先。
- "EN / 中"切换中英界面：节点标签、领域名、详情面板、按钮与提示全部双语（节点正文仍为中文），选择存 localStorage；领域英文名维护在 `_meta.yaml` 各领域的 `name_en` 字段。
- "学习树"开关左侧树状学习图：双击/搜索进入的节点按相关度挂到最相关根下（强相关正常、弱相关弱化、无相关询问建新根）；正文超链接进入无条件挂到最近根下；支持拖拽改父子、设为根、移除、折叠；可"保存"命名存入森林、"森林"载入/删除，`localStorage` 自动长期保存。
